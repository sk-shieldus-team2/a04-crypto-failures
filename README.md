# SK쉴더스 미래내일 일경험 2팀 클라우드 보안 프로젝트

OWASP A04 암호화 실패 취약점을 직접 만들어 공격하고 조치해 보는 프로젝트입니다.
웹 서버와 WAS, 데이터베이스로 이어지는 3계층 환경에 취약본과 조치본을 두고
무엇이 문제이고 어떻게 고치는지를 비교합니다.

## 기술 구성

1. 웹 서버: nginx (8080 포트)
2. WAS: WebLogic 14.1.2 (7001 포트)
3. 데이터베이스: Oracle XE 21c (취약 앱용), PostgreSQL (인프라 진단용)
4. 애플리케이션: Java
5. 로컬 실습: Docker Compose

## 폴더 구조

```
.
├── web/          nginx (vuln, fixed)
├── was/          WebLogic (vuln, fixed) + 설치/도메인 스크립트
├── db/
│   ├── oracle/   취약 앱 DB (vuln, fixed)
│   └── postgres/ 인프라 진단용
├── docs/         수행계획서, 시나리오, 보고서
├── .github/      CI/CD 워크플로우
└── docker-compose.yml   로컬에서 3계층을 한 번에 띄우는 용도
```

## 로컬 실행

### 사전 준비 (처음 한 번)

실행 전에 두 가지를 먼저 준비합니다. 이 과정을 건너뛰면 빌드가 실패합니다.

1. WebLogic 설치 파일을 `was/installer/` 폴더에 넣습니다. 이 파일은 용량과
   라이선스 때문에 저장소에 없으므로, 팀 내부에서 전달받아 넣습니다. 없으면
   빌드가 설치 파일이 없다는 오류로 멈춥니다.
2. 비밀번호를 담을 `.env`를 만듭니다. 저장소에는 값을 비운 예시만 있으므로
   복사해서 각자 채웁니다.

```bash
cp .env.example .env     # 복사한 뒤 비밀번호 입력
```

### 실행

사전 준비가 끝나면 아래 명령으로 전체를 올립니다.

```bash
docker compose up -d --build
```

컨테이너가 다 올라오면 `http://localhost:8080` 으로 접속합니다. WebLogic은 기동에
1분에서 2분 걸리니 그 뒤에 애플리케이션 접속을 확인합니다.
